## 1. Overview and Scope

The Games Discovery, Tournaments, Semantic Search, and Analytics module delivers three core capabilities:
1. **Game Discovery & AI Semantic Search:** Natural-language search powered by PostgreSQL `pgvector`, using genuine 384-dimensional dense vectors generated by the local open-source transformer model `Xenova/all-MiniLM-L6-v2` and indexed with an HNSW cosine distance index.
2. **Competitive Tournaments & Capacity Control:** Event creation, slot capacity limits, registration deadlines, and concurrency-safe customer self-registration backed by database row locking (`SELECT ... FOR UPDATE`).
3. **Operational & Financial Analytics:** Comprehensive reporting views (`vw_popular_games`, `vw_pc_usage_summary`, `vw_daily_revenue`) with strict role-based financial masking (revenue is admin-only).

## 3. Database Architecture (`004_games_analytics.sql`)

### 3.1 Games & Embedding Metadata
* `embedding_model TEXT`: Records model version (`Xenova/all-MiniLM-L6-v2`) for reproducibility and stale-vector detection.
* `embedding_updated_at TIMESTAMPTZ`: Timestamp when vector was computed.
* `is_active BOOLEAN NOT NULL DEFAULT TRUE`: Soft-archival flag. Inactive games are hidden from default catalogue views and the session-games picker.
* **Vector Index:** Partial HNSW cosine index `games_search_embedding_hnsw_idx` on `search_embedding vector_cosine_ops WHERE search_embedding IS NOT NULL`.

### 3.2 Tournaments & Concurrency Safety
* Columns: `status` (`draft`, `open`, `closed`, `completed`, `cancelled`), `max_participants`, `registration_deadline`, `description`.
* **Locking Trigger:** `games_guard_tournament_registration` on `tournament_registrations` runs `BEFORE INSERT` and locks the parent tournament row `FOR UPDATE`. It verifies status is `open`, deadline has not passed, and `COUNT(*) < max_participants`, preventing race-condition overbooking.

### 3.3 Historical Preservation (Cascade Elimination)
* Replaced `ON DELETE CASCADE` with `ON DELETE RESTRICT` on:
  * `session_games.session_id` and `session_games.game_id`
  * `tournament_registrations.tournament_id` and `tournament_registrations.customer_id`
* Deleting games or tournaments with historical records is rejected with `409 Conflict`.

### 3.4 Security-Invoker Views
* `vw_popular_games`: Joins `games`, `game_categories`, and `session_games` to aggregate play counts and recorded minutes.
* `vw_pc_usage_summary`: Joins `gaming_pcs` and `gaming_sessions` to report completed sessions and observed playtime.
* `vw_daily_revenue`: Unifies three distinct revenue streams (`session`, `snack_order`, `membership`) without double-counting.
* **Security:** All views use `WITH (security_invoker = true)` and have privileges revoked from `anon` and `authenticated`.

## 4. API Specification

* `GET /api/games`: Returns active games with category and embedding status. Admin can request `all=true`.
* `POST /api/games`: Admin-only; creates game and immediately computes 384-d vector.
* `PATCH /api/games/[gameId]`: Admin-only; regenerates vector only if title, category, or description changes.
* `DELETE /api/games/[gameId]`: Admin-only; returns 409 if session plays or tournaments reference the game.
* `POST /api/search/games`: Validates query prompt (2–300 chars), computes query embedding, and returns nearest games via pgvector `<=>` cosine distance.
* `GET/POST /api/tournaments`: Lists tournaments; creates tournament with capacity and deadlines.
* `POST /api/tournaments/[tournamentId]/registrations`: Registers customer; enforces row locking and translates duplicates to 409.
* `DELETE /api/tournaments/[tournamentId]/registrations`: Cancels registration if before deadline.
* `GET /api/analytics/popular-games`: Returns games ranked by play count and genre breakdowns.
* `GET /api/analytics/pc-usage`: Returns PC station observed usage; masks revenue for staff.
* `GET /api/analytics/revenue`: Admin-only; returns daily revenue and breakdown by stream.
